# Matriz de Edición por Entidad (BD ↔ DTO ↔ Formulario)

Este documento audita y consolida la correspondencia exacta entre las columnas de base de datos (`startdb.pgsql`), los campos aceptados por los DTOs de actualización en la API (`Update*Request` en Go) y los campos disponibles en los formularios de edición del frontend (`importadoraInterfaz`).

## Reglas del Proyecto
1. **Correspondencia total:** Todo campo editable en base de datos y en el DTO debe estar disponible en el formulario de edición correspondiente.
2. **Precarga completa:** El formulario precarga siempre el objeto completo desde el detalle (`GET /:id` o su endpoint equivalente), nunca de la fila de la tabla paginada.
3. **Vaciado de campos opcionales:** Si el usuario borra el contenido de un campo opcional, el frontend envía `""` o `null` (no `undefined` que omita el campo) y el servicio en Go almacena `NULL` en PostgreSQL mediante `cleanOptString` o equivalente.
4. **Estado reactivo:** Al guardar, el store de Redux Toolkit se actualiza con la respuesta devuelta por el endpoint `PUT`, reflejándose de inmediato sin recargas forzadas.
